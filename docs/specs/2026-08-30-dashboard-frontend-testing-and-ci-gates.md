# Architectural Specification: Console Frontend Testing & CI Verification Gates

**Author**: Aerial Monorepo Architecture Squad (Frontend, CI/CD, SRE, Devil's Advocate)  
**Date**: 2026-08-30 (updated 2026-11-13 after the React console cutover)  
**Target Services**: `services/console/ui`, `services/console`, `.github/workflows/docker-publish.yml`, `scripts/verify.sh`, `scripts/check-coverage.sh`  
**Status**: APPROVED & IMPLEMENTED  

---

## 1. Context & Motivation

The console (`services/console`) serves the operator HUD: real-time queue state, cluster telemetry, deployment pipelines, schedules, the memory archive and the Vanadis build queue. The UI is a React + TypeScript app in `services/console/ui`, bundled with Vite and served by the Go console binary.

The original version of this spec gated a hand-written `static/app.js` with `node --test` unit tests and `node --check` syntax checks, after a missing helper caused a runtime `ReferenceError` and a false `OFFLINE` alarm. That UI has been retired. This spec now describes the gates that protect the React console.

---

## 2. Verification Gates

1. **Type checking**: `npm run typecheck` runs `tsc --noEmit` over the app and over the e2e suite (`e2e/tsconfig.json`), so a missing symbol fails before anything runs.
2. **Unit and component tests with coverage**: `npm run test:coverage` runs Vitest with V8 coverage. The thresholds live in `services/console/ui/vite.config.ts` (95% lines, branches, functions and statements) and Vitest exits non-zero when any of them is missed.
3. **Production build**: `npm run build` runs `vite build`, catching bundling and import errors the type checker cannot see.
4. **Browser end-to-end suite**: `npm run e2e` runs Playwright (`services/console/ui/e2e`) against the real console binary serving the built UI, with deterministic API fixtures from `e2e/fixtures` (regenerated by `npm run e2e:fixtures`).
5. **Go backend tests**: `go test` in `services/console` covers handlers, asset serving and config, under the monorepo Go coverage floor.

---

## 3. Where The Gates Run

### 3.1 CI (`.github/workflows/docker-publish.yml`)
- The `lint` job (**Lint Microservices & Frontend**) runs the "Console React UI Gates" step when console files change: `npm ci`, `npm run typecheck`, `npm run test:coverage`, `npm run build`.
- The `console-e2e` job (**Console UI E2E Suite**) builds the console binary, then runs `npm ci && npm run build && npm run e2e` inside the Playwright image whose tag matches the pinned `@playwright/test`, uploading `e2e/artifacts` on failure.
- Both feed the required **CI Gate** check, which depends on the job id `console-e2e`.

### 3.2 Local (`scripts/verify.sh`)
- `run_console_ui` runs typecheck, `test:coverage` and build (installing dependencies when `node_modules` is missing or stale).
- `run_console_e2e` runs the Playwright suite when a Playwright Chromium can launch locally; otherwise it prints a skip notice and leaves enforcement to the CI job.

### 3.3 Coverage reporting (`scripts/check-coverage.sh`)
- Reports the Go backend floor alongside the React console UI status, which reflects the Vitest thresholds above.

---

## 4. Verification & Sign-Off Criteria
1. Typecheck, Vitest (with thresholds met), build and the Playwright suite all pass in CI.
2. `./scripts/verify.sh --staged` passes locally for console changes.
3. The production image ships only the built bundle; Node dependencies are build-time only.
