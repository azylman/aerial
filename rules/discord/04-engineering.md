# Core Engineering, Testing & Deployment Invariants

1. **Physical Immutability & Ephemeral Workspaces**:
   - **Kernel Read-Only Invariant**: `/share/aerial-config` and `/share/aerial` are mounted strictly **read-only (`:ro`)** into `eri`. Direct file writes or local git mutations targeting `/share/*` will fail with `EROFS: Read-only file system`.
   - **Ephemeral Scratch Workspaces**: Author all code, configuration, persona, skill, and repository updates across ANY repository (`aerial`, `aerial-config`, `mirrormere`, `aerial-sidecars`, etc.) in isolated scratch clones initialized via `scripts/aerial-pr.sh init [repo]`. Never use wrapper scripts, manual clones, or raw GitHub MCP PR tools (`create_pull_request`, `merge_pull_request`).

2. **Continuous Deployment, PR Submission & Skill Trigger**:
   - **Scoped `self-improvement` Skill Activation**: Load `.agents/skills/discord/self-improvement/SKILL.md` when undertaking **Tier 2/3 features or refactors (>50 LOC), Girl Gang plan/diff reviews, Vanadis multi-chunk builds, database schema migrations, or CI/RoboRev failure remediation**. Tier 0 (≤5 LOC config/doc tweaks) and simple Tier 1 (<50 LOC single-package bugfixes/tests not touching SQL schemas, auth/security, concurrency/mutexes, Nomad topology, or core queue/runner loops) may execute directly following these invariants.
   - **Universal Asynchronous PR Submission (`scripts/aerial-pr.sh submit <scratch_dir> [commit_msg]`)**:
     - **Zero-Bypass Verification**: Always run `./scripts/verify.sh --staged` (and targeted package tests) locally before submitting; never commit or push unverified changes.
     - **Mandatory PR Descriptions**: Provide `PR_DESCRIPTION.md` in the scratch root (or `--body-file`) using the Inverted Pyramid format with zero markdown tables and a sanitized single-line title.
     - **Immediate Turn Termination**: `aerial-pr.sh submit` runs fast pre-flight verification, pushes the branch, arms native GitHub `SQUASH` auto-merge, and registers the PR for event-driven continuous delivery. **The active turn MUST terminate immediately upon PR submission**—never poll CI in foreground `sleep` loops or schedule PR follow-up reminders.
   - **Event-Driven CI Remediation**: Green CI merges and deploys automatically via `webhooks-router` and `hangar`. If CI checks or `roborev` fail and wake `eri`, consult `.agents/skills/discord/self-improvement/SKILL.md` (Section 3) to proactively remediate the branch or record a verified technical override.

3. **Core Software Engineering & Hermetic Testing Invariants**:
   - **Production Database, Single-Service Table Ownership & Declarative Migrations**: Production runs on PostgreSQL 18 with `pgvector`. Every table in `schema.sql` is owned and queried by a single service; cross-service interaction happens over HTTP/MCP APIs rather than shared SQL queries. Define all schema modifications declaratively in `schema.sql`. Writing imperative DDL (`ALTER TABLE`, `DROP TABLE`) in application code or startup hooks is strictly prohibited and blocked by `scripts/verify.sh`. When modifying `schema.sql`, load and follow `.agents/skills/discord/self-improvement/references/atlas-migrations.md`.
   - **Pure Constructor Injection & Functional Core / Imperative Shell**: Require explicit dependencies in constructors; workers read dynamic config JIT via `cfg.Current()` snapshots rather than caching scalars. Factor business logic into pure, deterministic functions tested via fast (<1ms) table-driven unit tests; reserve mock runners and subprocess orchestration strictly for concurrency plumbing.
   - **Test Purity, Defense-in-Depth & Isomorphism**:
     - Assert observable behavior using hand-derived literals or static fixtures—never internal constants, exact log wording, or values computed by the helper under test. Never assert on mock internal call counts; mock only external boundaries (`git`, Docker, Discord REST, DB, `runner.RunAgy`) with full intra-package parallelism (`t.Parallel()`), and keep test-only hooks out of production structs.
     - Validate inputs across all layers (API entry, domain logic, environment guards).
     - **Isomorphism Rule**: Only unify functions, handlers, types, or test cases when they share the **exact same data contract and control-flow shape**—never merge heterogeneous behaviors behind mode-discriminator switches (`switch tc.mode`) or one-hot boolean flags (`isScenarioA: true`).
   - **Homogeneous Table-Driven Tests & Zero Closure/Subtest Concatenation**: Exercise each function under test via one unified `tests := []struct{...}` table and one `for _, tc := range tests { t.Run(tc.name, ...) }` loop using declarative expectation fields. Anonymous closure fields (`run`, `check`, `extraCheck`, `setup`, `validate`, `validator`, `verify`, `lookup` `func(...)`), mode-switch union tables, and pasting imperative test bodies into sequential hardcoded `t.Run("LiteralName", ...)` blocks are strictly prohibited. Use 1-line positional fixture constructors and shared declarative mock servers so table rows remain compact under `gofmt`.
   - **Hermetic Fixtures, Zero Sleeps & Signal Safety**:
     - Storage/DB tests must use airgapped in-memory handles or `t.TempDir()`—never write to `/data` or `/share`.
     - Live `agy` binaries (`runner.RunAgy`) and live shell subprocesses must never run during unit tests.
     - Arbitrary sleeps (`time.Sleep`) are strictly prohibited in tests and production plumbing; use event-driven channels, condition variables, or injected delay overrides.
     - Never execute raw POSIX signal broadcasts (`syscall.Kill` with negative or arbitrary PIDs) in tests; use dependency-injected mock functions (`killProcessGroupWith`, `terminateProcessGroupWith`).
   - **Host-Native Tooling & Single-Pass Coverage**: Invoke `go test`, `node --test`, `golangci-lint run`, and `./scripts/verify.sh` directly in the workspace shell (never wrap unit tests in `docker run`; clean up any required test containers deterministically; build images with `DOCKER_BUILDKIT=1`). When statement coverage falls below 95%, audit gaps locally in a single pass via `./scripts/check-coverage.sh --service <svc> --check --gaps` and fold missing branch cases into existing canonical function tables (never append catch-all `*Coverage*` or `*Branches*` test functions at EOF).
