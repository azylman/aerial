# Aerial Go Service Architecture, Hermetic Testing & Durable Execution Invariants

Load this reference alongside the pinned community Go skills (`golang-code-style`, `golang-safety`, `golang-concurrency`, `golang-context`, `golang-error-handling`, `golang-testing`, `golang-modernize`, `golang-performance`, `golang-structs-interfaces`) whenever authoring, reviewing, refactoring, or testing Go (`.go`) code across Aerial repositories:

- **Canonical Go Service Package Layout (L0 -> L3)**:
  - Root `package main` (`services/<svc>`, `mcp/<srv>`) is capped at 3 files (`main.go`, `main_test.go`, `goleak_test.go`) for bootstrap/wiring only; domain packages live under `internal/*` ordered strictly `L0` (`internal/config`, `internal/model` — zero sibling `internal/*` or `pgx` imports) -> `L1` (`internal/store`, outbound clients) -> `L2` (`internal/mcp`, `internal/tools`, `internal/service`, `internal/ticker`) -> `L3` (`internal/server`, `internal/router`). Horizontal grab-bag filenames (`pure.go`, `helpers.go`, `utils.go`, `common.go`, `types.go`, `frozen.go`, `*_part[0-9]*_test.go`) and `func(...)` fields inside `[]struct{...}` test tables are prohibited.
- **Homogeneous Table-Driven Tests & Zero Closure/Subtest Concatenation**:
  - Group test cases into a `tests := []struct{...}` table only when every row shares the same setup, call, and assertion shape (capped at <=16 struct fields via `st.Fields.NumFields()` with zero one-hot setup-mode flags like `nilPool` or `useHook`). When a function has distinct lifecycle phases, execution modes, or boundary/nil/fault guards, split them into separate behavior-named `Test<Func>_<Behavior>` functions with compact behavior-scoped tables. Anonymous closure fields (`run`, `check`, `extraCheck`, `setup`, `validate`, `validator`, `verify`, `lookup` `func(...)`), mode-switch union tables, and pasting imperative test bodies into sequential hardcoded `t.Run("LiteralName", ...)` blocks are strictly prohibited. Use 1-line positional fixture constructors and shared declarative mock servers so table rows remain compact under `gofmt`.
- **Hermetic Fixtures, Zero Sleeps & Signal Safety**:
  - DB-backed tests for Postgres services use `pkg/pgtest`: `TestMain` calls `os.Exit(pgtest.Main(m))` (one throwaway Postgres 19 + pgvector per package, loaded from the real `schema.sql`) and each test opens `pgtest.NewDSN(t)` (a private cloned database) with the production constructor. Never use SQLite or scripted fake drivers for them; force driver failures with a closed handle, a cancelled context, a constraint violation or DDL sabotage of the test's own clone. `pgtest`'s `initdb`/`pg_ctl` are the only sanctioned test subprocesses. Other file-backed tests use `t.TempDir()`—never write to `/data` or `/share`.
  - Live `agy` binaries (`runner.RunAgy`) and live shell subprocesses must never run during unit tests.
  - Arbitrary sleeps (`time.Sleep`) are strictly prohibited in tests and production plumbing; use event-driven channels, condition variables, or injected delay overrides.
  - Never execute raw POSIX signal broadcasts (`syscall.Kill` with negative or arbitrary PIDs) in tests; use dependency-injected mock functions (`killProcessGroupWith`, `terminateProcessGroupWith`).
- **Restate Durable Execution & Virtual Object Invariants**:
  - Wrap all non-deterministic operations and external I/O (PostgreSQL, HTTP, NATS, Discord, `time.Now()`, random/UUIDs) inside `restate.Run(ctx, func(rc restate.RunContext) (T, error) { ... }, restate.WithName("<step>"))` (or use `restate.UUID(ctx)` / `restate.Rand(ctx)` / deterministic `uuid.NewSHA1` from `ctx.Request().ID`).
  - Inside `restate.Run`, pass strictly the inner `rc` (`restate.RunContext`) to downstream calls and NEVER invoke outer `restate.Context` operations (`restate.Get`, `Set`, `ObjectSend`, `Sleep`, or nested `Run`).
  - Never use raw goroutines, channels, `select`, or Go `map` iteration order to drive Restate operations in replayable handler code outside `restate.Run` (use `restate.Wait` / `restate.WaitFirst` and sort map keys first to prevent `RT0016` journal mismatch).
  - Convert non-retryable 4xx/validation/not-found/conflict/fencing errors via `restate.ToTerminalError(err, restate.WithErrorCode(...))` (including inside `restate.Run` callbacks); terminal code 409 is reserved for Restate's own cancellation, so conflicts/fencing/stale state use 412 and deterministic Postgres SQLSTATEs (classes 22, 23, 42, 0A, 2B, 2D, 25) are classified terminal while the rest retry; leave retries to the server default policy (about an hour, then pause) with no step caps or per-service retry overrides; never hold an exclusive `restate.ObjectContext` lock across sleeps or backoff loops (return promptly and use `restate.ObjectSend(...).Send(req, restate.WithDelay(d))`).
  - Always send a deterministic `Idempotency-Key` matched 1:1 to the logical operation identity (never omit or randomize per attempt, include schedule tick or attempt ordinal boundaries when `SkipIfActive` early returns can be memoized, and strip wall-clock publish timestamps or fan-out noise that defeat deduplication); declare `restate.WithInactivityTimeout` / `restate.WithAbortTimeout` on reflected services and use `context.WithoutCancel(ctx)` for post-commit finalization checks.
  - In Vanadis, `failed` is a recoverable pause state—never terminal; only `completed` and `cancelled` may call `restate.ClearAll(ctx)`.
  - When authoring or modifying Restate services, Virtual Objects, or workflows (`github.com/restatedev/sdk-go`), load and follow [`.agents/skills/discord/self-improvement/references/restate-workflows.md`](restate-workflows.md).
- **Host-Native Tooling & Single-Pass Coverage**:
  - Unit tests, non-Go `sh_test` gates, and the 95% statement coverage floor run via Bazel 9.3.3 (`bazel test`, `bazel coverage`, `./scripts/verify.sh --staged`, and `bazel coverage //<pkg>:all` with ephemeral Gazelle `BUILD.bazel` generation via `ensure_bazel_build_files` and LAN `bazel-remote` caching in-cluster), while container images build via `rules_oci` (`images/BUILD.bazel`) or `DOCKER_BUILDKIT=1` for retained Dockerfiles. When statement coverage falls below 95%, audit gaps locally in a single pass via `bazel coverage //<pkg>:all` (inspecting `coverage.dat` / `coverage-gate.awk` per-package output) and fold missing branch cases into matching behavior-scoped test tables (or a dedicated behavior-named `Test<Func>_<Behavior>` table when setup shape differs; never bolt one-hot mode flags onto an existing struct beyond 16 fields and never append catch-all `*Coverage*` or `*Branches*` test functions at EOF).
